状态：**待批准（draft）** · 归属：[`SPEC-BOOKSOURCE-REVAMP.md`](./SPEC-BOOKSOURCE-REVAMP.md) 模块 `detect-ui`

> 常驻的底部作业条。完整设计见 [`SPEC-BOOKSOURCE-LAYOUT.md`](./SPEC-BOOKSOURCE-LAYOUT.md) §3.3–§3.4。

## Objective

让「检测」从一个黑箱长任务变成用户能看见、能中断、能读懂的事，并让检测出来的坏源可以被消费掉。

现状的三个具体问题：进度只在按钮文字上（「处理中…」）；结果只在一个抽屉里、与列表脱节；判定口径的
长段解释文案常驻在列表上方（`pages/BookSourceManage.ets:448-453`）。

## Non-goals

- 不做检测调度与落盘（那是 `detect-job`）。
- 不重新定义可用性语义（见下，沿用现有四态）。
- 不在本模块做书源列表的搜索/筛选/分组（那是 `source-list`）；本模块只**展示**检测态。

## 必须保留的语义（现状是对的，不要改）

`pages/BookSourceManage.ets:24-70` 的四态划分与文案是有价值的，逐条沿用：

| 态 | 含义 | 是否参与一键清理 |
|---|---|---|
| 可用 `ok` | 完整链路通过 | — |
| 无结果 `noResult` | 探测词未命中，**源未必失效** | ❌ |
| 超时 `timeout` | 请求超时，可能是瞬时 | ❌ |
| 不可用 `unavailable` | 链路失败（网络 / 解析 / 规则缺失等） | ✅ |

「仅不可用参与一键清理」这个设计是对的，务必保留。新增的 L1 预检会增加一个维度（
「预检通过但未跑完整链路」），它属于**未验证**而不是**可用**——不要把它标成绿色。

## 关键设计决策

**1. 进度常驻。** `detect-job` 是进程级单例，因此进度可以跨段、跨页面存活。落地形态：书源页底部
**跨段常驻作业条**（四态定义见 [`SPEC-BOOKSOURCE-LAYOUT.md`](./SPEC-BOOKSOURCE-LAYOUT.md) §3.4）；
页外可见性由长时任务的系统通知承担。必须满足：离开书源页再回来，进度仍在且是活的。

进度内容：`已完成 / 总数`、当前批、模式（预检 / 完整）、已耗时、预计剩余、**取消**按钮。

**2. 结果面（消费检测结果）。** 位于「检测」段的页内（不再用抽屉，见布局文件 §4.1）。

- 按检测态筛选（与 `source-list` 的筛选维度**共用同一套**，不要定义第二套）。
- 批量动作：关闭不可用 / 删除不可用 —— 保留但**降权**（现状主按钮是品牌红的「删除全部不可用」，
  3000 源下这是把删除放在最显眼的位置；改为次级样式 + 二次确认 + 明确条数）。
- 结果面的列表必须用 `LazyForEach`（现状抽屉里是 `ForEach`，`:470`）。

**3. 判定口径文案改成按需展开。** 那段「可用=完整链路通过；无结果=…」的解释是对的，但不必常驻；
收进「这是什么？」或结果面的说明入口。

**4. 检测范围入口。** 由 `detect-engine` / `detect-job` 支持后，本模块提供选择：

- 全部（含警告：3000 源大概要多久）
- 仅未测 / 仅上次失败（**增量默认档**，窗口 7 天，见 plan A8）——依赖 `source-store` 的
  `last_detect_at` / `last_detect_state`
- 按分组 —— **分组来源 = `bookSourceGroup` 字段**（`source-store` 的 `grp` 列，已定 2026-10-14）
- 仅当前筛选结果 / 仅选中项（依赖 `source-list` 的多选模式，见其开放问题 5，**可后置**）

默认档是**增量**而不是全部；另留「全部重测」入口。

**5. 三态呈现。** 进行中 / 已完成 / 已取消。已取消时展示已得的部分结果并给「继续」入口
（状态在 `detect-job`，本模块只读）。

## Success Criteria

1. 检测期间 UI 完全可交互：滚动、搜索、切页都不卡（进度更新按批，不是按源）。
2. 离开书源页再回来，进度仍在且继续推进。
3. 取消可达且立即反馈（按钮进入「正在停止…」态，≤ 1 批内转为已取消）。
4. 「无结果 / 超时」在结果面上**不出现**一键清理入口，文案明确说明它们不参与清理。
5. 结果面 3000 条用 `LazyForEach`，滚动流畅；进度条在书源段与检测段都可见。
6. 首次使用检测功能时，用户能知道「全部」大约要多久，以及为什么默认只测未测/失败的源。
7. 页外（离开书源页）时，长时任务通知可作为回到进度的入口。

## Boundaries

- **Ask first**：若结果面继续用 `BottomDrawer`，改动要同步 `docs/specs/UI-SPEC.md` 的调用点清单；
  若改为页内嵌，则**减少**一个调用点，同样要同步该文件。
- **Never**：在 `build` 里对 `detectResults` 做 filter/sort/map；把「未验证」当作「可用」展示；
  把删除放在没有二次确认的显眼主位。

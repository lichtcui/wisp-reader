## Objective

让「检测」从一个黑箱长任务变成用户能看见、能中断、能读懂的事，并让检测出来的坏源可以被消费掉。

现状的三个具体问题：进度只在按钮文字上（「处理中…」）；结果只在一个抽屉里、与列表脱节；判定口径的
长段解释文案常驻在列表上方（`pages/BookSourceManage.ets:448-453`）。

## Non-goals

- 不做检测调度与落盘（那是 `detect-job`）。
- 不重新定义可用性语义（见下，沿用现有四态）。
- 不在本模块做书源列表的搜索/筛选/分组（那是 `source-list`）；本模块只**展示**检测态。

## 必须保留的语义（现状是对的，不要改）

`pages/BookSourceManage.ets:24-70` 的四态划分与文案是有价值的，逐条沿用：

| 态 | 含义 | 是否参与一键清理 |
|---|---|---|
| 可用 `ok` | 完整链路通过 | — |
| 无结果 `noResult` | 探测词未命中，**源未必失效** | ❌ |
| 超时 `timeout` | 请求超时，可能是瞬时 | ❌ |
| 不可用 `unavailable` | 链路失败（网络 / 解析 / 规则缺失等） | ✅ |

「仅不可用参与一键清理」这个设计是对的，务必保留。新增的 L1 预检会增加一个维度（
「预检通过但未跑完整链路」），它属于**未验证**而不是**可用**——不要把它标成绿色。

## 关键设计决策

**1. 进度跨页面存活，但只在一个地方显示。** `detect-job` 是进程级单例，因此进度可以跨页面存活。
落地形态：**任务态整页检测视图**（`components/DetectProgressCard.ets`；三态定义见
[`SPEC-BOOKSOURCE-LAYOUT.md`](./SPEC-BOOKSOURCE-LAYOUT.md) §3.3）；页外可见性由长时任务的系统通知承担。
必须满足：作业仍在跑时离开书源页再回来 → 自动回到任务态，进度是活的。
**冷启动只有 `status === running` 才进任务态**，已完成 / 已取消的历史轮次不占屏。

进度内容：`已完成 / 总数`、模式（预检 / 完整）、已耗时、预计剩余、后台态、**取消**按钮。
**同一次作业不得有两个显示面**——旧版「检测段作业卡 + 跨段常驻底部作业条」同时表达同一份进度，已撤。

**2. 结果面 = 书源列表本身（2026-11-02）。** 不再有独立的「结果面」列表：

- 检测结束后失败源已按 [`SPEC-BOOKSOURCE-LAYOUT.md`](./SPEC-BOOKSOURCE-LAYOUT.md) §3.2 的三档排序
  浮到列表最前；用户点「返回书源列表」即看到结果。没有第二个大列表，也就没有第二套筛选维度。
- 批量动作：关闭不可用 / 删除不可用 —— 保留但**降权**，挂在**检测结束态的清理分区**上（检测刚结束时正是它
  最有用的时候）：次级样式 + 二次确认 + 明确条数 + 口径说明，仍走 `setEnabledMany` / `removeMany` 批量事务。
- 摘要卡只报**整库口径**的不可用条数（`DetectJobRunner` 没有按轮次暴露结果 API）；
  **不得**把「本轮已检测 N 个」写成「可用 N 个」。

**3. 判定口径文案改成按需展开。** 那段「可用=完整链路通过；无结果=…」的解释是对的，但不必常驻；
收进「这是什么？」或结果面的说明入口。

**4. 检测范围入口（2026-11-02 收敛）。** 不再有范围条 / 二级选择器：**范围与计数直接写在 `⋯` 菜单项上**。

- `检测书源（增量 N）` → `probe`（L1 预检）：N = 未测 + 上次失败 + 7 天未检的启用源（plan A8），
  依赖 `source-store` 的 `last_detect_at` / `last_detect_state`；N = 0 时该项禁用。
- `全部重测（M）` → `full`：M = 启用源总数；M = 0 时该项禁用。
- **按分组检测已撤**（分组选择器随筛选条一起撤，见布局文件 §7）；「仅选中项」仍可后置，
  依赖 `source-list` 的多选模式（其开放问题 5）。

默认入口是**增量**而不是全部；「全部重测」并列成第二个菜单项。

**5. 三态呈现。** 进行中 / 已完成 / 已取消。已取消时展示已得的部分结果并给「继续」入口
（状态在 `detect-job`，本模块只读）。

## Success Criteria

1. 检测期间 UI 完全可交互：任务态下**取消**即时可达，切页不卡（进度更新按批，不是按源）。
2. 作业仍在跑时离开书源页再回来 → 自动回到任务态，进度继续推进（冷启动靠 `DetectJobRunner.restore`）。
3. 取消可达且立即反馈（按钮进入「正在停止…」态，≤ 1 批内转为已取消），取消后停在摘要卡。
4. 一键清理入口**只按 `unavailable` 计数**：「无结果 / 超时」不参与，摘要卡文案明确它们不属于不可用。
5. 常态下整页只有头行 + 书源列表；任务态下整页只有检测视图（页内头行 + 进度 / 摘要 / 操作）——
   同一个作业不会出现两份进度，也不出现居中浮卡式的「弹窗」观感。
6. `检测书源（增量 N）` / `全部重测（M）` 的计数即范围：用户点开菜单就知道这一轮会测多少。
7. 页外（离开书源页）时，长时任务通知可作为回到进度的入口。

## Boundaries

- **Ask first**：若结果面继续用 `BottomDrawer`，改动要同步 `docs/specs/UI-SPEC.md` 的调用点清单；
  若改为页内嵌，则**减少**一个调用点，同样要同步该文件。
- **Never**：在 `build` 里对 `detectResults` 做 filter/sort/map；把「未验证」当作「可用」展示；
  把删除放在没有二次确认的显眼主位。
